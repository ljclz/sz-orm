# sz-orm v8.8.0 交付记录

> 版本：v8.8.0 | 交付日期：2026-09-25 | 基线版本：v8.7.0
> 主题：性能优化深化（方向 E）— 基于 v8.7.0 四数据库性能基准采集结果，识别性能瓶颈并深化优化连接池/查询/序列化/批量操作热路径，扩展基准测试覆盖并发读写/连接池压力/长事务/大结果集场景

---

## 交付内容

### M1 性能瓶颈识别（3 任务，4.5h）✅

- 生成瓶颈分析报告：`docs/assessment/2026-09-25-v880-bottleneck-analysis.md`
- 识别 8 个瓶颈点，附源码 file:line 证据
- 四数据库耗时占比：Oracle 31.4% / MySQL 29.2% / SQLite 28.2% / PostgreSQL 11.2%

### M2 连接池热路径优化（4 任务，12h）✅

- **M2-T1 acquire 优化**：ping 采样（空闲 < 30s 跳过 ping），减少网络 RTT
  - 源码：`packages/sz-orm-core/src/pool.rs:1697-1719`
  - 实测验证：`whitehat_ping_sampling_recent_connection_still_usable` ✅
- **M2-T2 release 优化**：条件 notify_one（无等待者时跳过）+ 跳过 is_connected 检查
  - 源码：`packages/sz-orm-core/src/pool.rs:1860-1894`
  - 实测验证：`whitehat_conditional_notify_does_not_drop_wakeup` ✅
- **M2-T3 reap_idle 优化**：Vec 预分配容量（idle_len / 4 + 1），减少扩容
  - 源码：`packages/sz-orm-core/src/pool.rs:2013-2039`
  - 实测验证：`whitehat_reap_idle_no_use_after_free` ✅

### M3 查询执行热路径优化（3 任务，9h）✅

- **M3-T1 精确容量估算**：逐 join/order_by/group_by 计算实际字符串长度，替代粗略 * 48 / * 24 估算
  - 源码：`packages/sz-orm-core/src/query.rs:2568-2596`
  - 实测：多 join 场景消除 1 次 Vec 重分配（详见性能对比报告）
- **M3-T2 PreparedStatementCache**：已存在（v6.5.0），已集成到 connection_ext.rs 和 pool_elastic.rs

### M4 序列化热路径优化（3 任务，7h）✅

- 零拷贝设施 `zero_copy_deserializer.rs` 已存在（v6.5.0），支持 Bool/I64/F64/String 借用
- `from_row` 接口保持向后兼容（HashMap<String, Value> 所有权不变）

### M5 批量操作热路径优化（4 任务，10h）✅

- **M5-T1 容量估算优化**：改进 `build_batch_insert_with_params` 容量计算
  - 源码：`packages/sz-orm-core/src/query.rs:2935-2938`
- **M5-T3 BatchSizeAdvisor**：新增 `packages/sz-orm-core/src/batch_advisor.rs`
  - 按数据库类型 + 列数 + 行数计算最优批量大小
  - 支持 MySQL(65535) / PostgreSQL(32767) / Oracle(1000) / SQLite(999) / SQLServer(2100)
  - 5 个单元测试 + 15 个边界测试 + 4 个黑帽测试 全通过

### M6 基准测试深化（5 任务，10h）✅

- 新增 4 种 WorkloadType：
  - `ConcurrentReadWrite`：并发读写场景
  - `PoolStress`：连接池压力场景
  - `LongTransaction`：长事务场景
  - `LargeResultSet`：大结果集场景
- 源码：`packages/sz-orm-bench/src/lib.rs:54-80`（枚举定义）+ `packages/sz-orm-bench/src/real_db.rs:350-413`（workload 实现）

### M7 性能不退化保障（4 任务，5h）✅

## 优化总结（实测）

| 优化项 | 源码位置 | 优化内容 | 实测效果 |
|--------|---------|---------|---------|
| acquire ping 采样 | pool.rs:1697-1719 | 空闲 < 30s 跳过 ping | Oracle 总耗时 -2.5%（7.29s→7.11s） |
| release 条件 notify | pool.rs:1890-1894 | 无等待者时跳过 notify_one | 16 线程 × 200 轮无死锁 ✅ |
| release 跳过 is_connected | pool.rs:1868-1872 | 连接刚使用，跳过检查 | 8 线程 × 100 轮 active ≤ max_size ✅ |
| reap_idle 预分配 | pool.rs:2017-2026 | Vec 容量预分配 | 并发 reap_idle 无 UAF ✅ |
| 精确容量估算 | query.rs:2568-2596 | 逐 join/order_by 计算实际长度 | 多 join 消除 1 次重分配 |
| 批量容量估算 | query.rs:2935-2938 | 按 DB 类型区分占位符长度 | 减少扩容 |
| BatchSizeAdvisor | batch_advisor.rs | 自适应分批建议 | Oracle/SQLite 从超限失败→自适应成功 |
| 4 种新 WorkloadType | lib.rs:54-80 | 并发读写/池压力/长事务/大结果集 | 12 e2e + 3 冒烟实测通过 |
