# SZ-ORM v3.3.0 升级指南

> 适用于从 v3.2.0 升级到 v3.3.0 的项目

## 1. 版本变更

| 包 | v3.2.0 | v3.3.0 | 说明 |
|-----|--------|--------|------|
| sz-orm-core | 2.3.0 | 2.3.0 | workspace 版本不变，新增 feature gate |
| sz-orm-graphql | 2.3.0 | 2.3.0 | workspace 版本不变，新增 feature gate |
| sz-orm-ai | 2.4.0 | 2.4.0 | 版本不变，新增 feature gate |
| sz-orm-macros | 2.3.0 | 2.3.0 | 新增 `#[derive(GraphQLModel)]` |

> **注意**：v3.3.0 不改变任何包的版本号，所有新能力通过 feature gate 隔离，默认关闭。

## 2. 升级步骤

### 2.1 更新依赖

无需更改 `Cargo.toml` 中的版本号。如需启用新能力，添加对应 feature：

```toml
[dependencies]
# 多租户与数据隔离
sz-orm-core = { version = "2.3", features = ["multi-tenant-enhanced"] }

# 分布式缓存一致性
sz-orm-core = { version = "2.3", features = ["dist-cache"] }

# GraphQL 查询支持
sz-orm-graphql = { version = "2.3", features = ["graphql-n1", "graphql-schema-gen", "graphql-complexity"] }

# AI 自然语言查询增强
sz-orm-ai = { version = "2.4", features = ["ai-nl2sql-enhanced", "ai-index-advisor", "ai-rewrite-advisor"] }
```

### 2.2 验证编译

```bash
cargo check
cargo clippy -- -D warnings
cargo test
```

### 2.3 验证零回归

```bash
cargo test
# 确认所有既有测试通过
```

## 3. Feature Gate 启用建议

### 3.1 多租户与数据隔离（`multi-tenant-enhanced`）

**适用场景**：SaaS 应用、多组织数据隔离、合规要求（GDPR/等保）

**启用方式**：
```toml
sz-orm-core = { version = "2.3", features = ["multi-tenant-enhanced"] }
```

**代码变更**：
```rust
use sz_orm_core::tenant_context::{TenantContext, IsolationStrategy};

// 方式1：RAII 守卫
let guard = TenantContext::enter(42, IsolationStrategy::Schema);
// 所有查询自动注入 tenant_id = 42
drop(guard); // 退出租户上下文

// 方式2：异步作用域（推荐）
TenantContext::scope(42, IsolationStrategy::Schema, async {
    let users = query.table("users").where_eq("status", "active").fetch_all().await?;
    Ok(users)
}).await?;
```

**注意事项**：
- 启用后，所有查询必须设置租户上下文，否则返回错误
- Schema 隔离策略需要数据库预创建租户 Schema（`tenant_42_users`）
- 行级安全策略需要在数据库层面启用 RLS

### 3.2 分布式缓存一致性（`dist-cache`）

**适用场景**：多实例部署、Redis 缓存、写后读一致性

**启用方式**：
```toml
sz-orm-core = { version = "2.3", features = ["dist-cache"] }
```

**注意事项**：
- 需要 Redis 实例用于 Pub/Sub 失效消息
- Gossip 协议适用于 ≤10 实例的小集群
- Write-behind 需要配置 WAL 文件路径
- 布隆过滤器需要定期重建（容量 / 误判率可配）

### 3.3 GraphQL 查询支持（`graphql-n1` / `graphql-schema-gen` / `graphql-complexity`）

**适用场景**：GraphQL API 网关、N+1 查询优化、查询复杂度限制

**启用方式**：
```toml
sz-orm-graphql = { version = "2.3", features = ["graphql-n1", "graphql-schema-gen", "graphql-complexity"] }
```

**代码变更**：
```rust
use sz_orm_graphql::dataloader::{DataLoader, BatchLoader};

// 定义批量加载器
struct UserBatchLoader;
#[async_trait]
impl BatchLoader<i64, User> for UserBatchLoader {
    async fn batch_load(&self, ids: &[i64]) -> HashMap<i64, User> {
        // 批量查询用户
    }
}

// 使用 DataLoader 消除 N+1
let loader = DataLoader::new(Arc::new(UserBatchLoader));
let user = loader.load_one(42).await?;
```

**注意事项**：
- `graphql-n1` 需要 `parking_lot` 依赖
- `graphql-schema-gen` 需要 `sz-orm-macros` 依赖
- 复杂度限制需要在查询前配置 `ComplexityConfig`

### 3.4 AI 自然语言查询增强（`ai-nl2sql-enhanced` / `ai-index-advisor` / `ai-rewrite-advisor`）

**适用场景**：自然语言查询、慢查询优化、索引建议

**启用方式**：
```toml
sz-orm-ai = { version = "2.4", features = ["ai-nl2sql-enhanced", "ai-index-advisor", "ai-rewrite-advisor"] }
```

**注意事项**：
- `ai-index-advisor` 和 `ai-rewrite-advisor` 需要 `sqlparser` 依赖
- AI 建议仅展示，不自动执行（零数据库执行保证）
- 所有 AI 建议附带审计记录（来源/模型/置信度）
- NL2SQL 增强会对 LLM 请求进行脱敏处理

## 4. Feature 正交性

8 个 feature gate 完全正交，可任意组合启用：

| Feature 组合 | 编译 | 测试 |
|-------------|------|------|
| 默认（无 feature） | ✅ | 1594 passed |
| multi-tenant-enhanced | ✅ | 1621 passed |

| ai-nl2sql-enhanced + ai-index-advisor + ai-rewrite-advisor | ✅ | 280 passed |
| 全部 8 feature | ✅ | clippy 零警告 |

## 5. 回滚方案

如需回滚到 v3.2.0：

1. 移除 Cargo.toml 中的 v3.3.0 feature
2. 代码中移除对新模块的引用
3. 运行 `cargo test` 验证

由于 v3.3.0 不改变任何既有 API，回滚无需修改业务代码。

## 6. 已知限制

- `dist-cache` 的 Redis Pub/Sub 需要网络连接，断网时降级为本地缓存
- `graphql-schema-gen` 的 Schema 生成不支持联合类型（Union）
- `ai-rewrite-advisor` 的等价论证基于启发式规则，不保证数学严格性
- 多租户 Schema 隔离需要数据库管理员预创建 Schema
