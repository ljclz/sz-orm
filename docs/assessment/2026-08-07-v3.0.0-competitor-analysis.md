## 三、优劣势分析

### 3.1 sz-orm 优势

| # | 优势 | 证据 | 竞争对手不具备 |
|---|------|------|---------------|
| 1 | **功能最全面** | 44 包覆盖 ORM + 事务 + AI + 图数据库 + FFI + WASM + 企业级 | 所有对手 |
| 2 | **N+1 自动消除** | SmartEagerLoader 60.6x 加速，N1QueryDetector 自动拦截 | SQLx/Diesel/SeaORM 均无 |
| 3 | **分布式事务完整** | 2PC + Saga + TCC + XA + 恢复，6 集成测试通过 | 所有对手均无 |
| 4 | **5 后端 + 图数据库** | MySQL/PG/SQLite/Oracle/MSSQL + Neo4j | Diesel/SeaORM 仅 3 后端 |
| 5 | **AI 查询优化** | 规则 + LLM 双引擎，EXPLAIN 5 方言解析，SQL 脱敏 | 所有对手均无 |
| 6 | **WASM + FFI** | 浏览器端 ORM + Python/JS 绑定 | 所有对手均无 |
| 7 | **下游验证** | sz-pay 5139 测试零回归 | 企业级验证 |

### 3.2 sz-orm 劣势

| # | 劣势 | 证据 | 竞争对手优势 |
|---|------|------|-------------|
| 1 | **社区生态小** | crates.io 下载量远低于 SQLx（~8M）/Diesel（~3M） | SQLx/Diesel 成熟社区 |
| 2 | **编译时 SQL 校验弱于 SQLx** | `query!` 宏需手动启用 db-verify，默认仅语法校验 | SQLx 默认连真 DB 校验 |
| 3 | **类型安全弱于 Diesel** | 运行时模型映射，非编译时 schema derive | Diesel 编译时强类型 |
| 4 | **代码量大** | 182K 行，编译时间长 | SQLx ~30K 行，SeaORM ~30K 行 |
| 5 | **文档不足** | 无系统用户文档，仅 AGENTS.md + SDD 文档 | SQLx/Diesel 有完整文档 |
| 6 | **GraphPool 用 Mutex** | `packages/sz-orm-graph/src/connection.rs` 非真正连接池 | — |
| 7 | **WASM 缺 TypeScript 定义** | 无 .d.ts 生成 | — |
| 8 | **rdkafka-sys 阻塞 --all-features** | Windows 无 librdkafka C 库 | — |

### 3.3 定位差异

| 产品 | 定位 | 适用场景 |
|------|------|----------|
| **SQLx** | 异步 SQL 工具包 | 需要编译时 SQL 校验、轻量级、社区成熟 |
| **Diesel** | 同步强类型 ORM | 需要最高类型安全、同步代码、PostgreSQL/MySQL/SQLite |
| **SeaORM** | 异步 ORM | 需要简单异步 ORM、基于 SQLx、社区活跃 |
| **sz-orm** | 全栈企业级 ORM | 需要多后端 + 分布式事务 + AI + 图数据库 + FFI + WASM + 企业级能力 |

## 四、结论

**sz-orm v3.0.0 在功能广度上显著领先所有 Rust ORM 竞争对手**（44 包 / 182K 行 / 5844 测试），特别是在分布式事务、AI 优化器、图数据库、WASM、FFI 等领域具有唯一性优势。

**主要短板在社区生态和文档**：crates.io 下载量远低于成熟竞品，缺乏系统用户文档。代码量大导致编译时间较长。

**建议下一步**：
1. 补充用户文档（API 文档 + 教程 + 示例）
2. 优化编译时间（feature gate 精细化）
3. GraphPool 改用 crossbeam-queue 连接池
4. WASM 生成 TypeScript 定义
5. 积极推广 crates.io 下载量
