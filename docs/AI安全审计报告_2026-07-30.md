#### C-1：MFA 密钥使用非密码学安全随机数生成

| 属性 | 值 |
|------|-----|
| **编号** | C-1 |
| **严重级** | Critical |
| **漏洞类型** | CWE-338: Use of Cryptographically Weak Pseudo-Random Number Generator |
| **OWASP** | A02:2021-Cryptographic Failures |
| **文件** | `packages/sz-orm-auth/src/mfa.rs:263-279` |

**描述**

`MfaSecret::new()` 调用 `generate_random_bytes(20)` 生成 MFA 密钥（用于 TOTP）。该函数使用 `std::collections::hash_map::DefaultHasher`（SipHash 1-2-3），仅以 `SystemTime::now().as_nanos()` 作为种子。

`DefaultHasher` **不是**密码学安全哈希函数，其输出可预测。种子仅为当前纳秒时间戳，攻击者若知道密钥生成的大致时间（误差 ±1 秒），仅需遍历约 10⁹ 个纳秒值即可复原密钥。

**代码片段**

```rust
// packages/sz-orm-auth/src/mfa.rs:263-279
fn generate_random_bytes(len: usize) -> Vec<u8> {
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    let mut result = Vec::with_capacity(len);
    let mut seed = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)
        .unwrap_or_default()
        .as_nanos();
    for i in 0..len {
        let mut hasher = DefaultHasher::new();
        seed.wrapping_add(i as u128).hash(&mut hasher);
        let h = hasher.finish();
        result.push((h & 0xFF) as u8);
        seed = seed.wrapping_add(h as u128);
    }
    result
}
```

**PoC（概念验证）**

1. 攻击者获取目标账户启用了 MFA 的大致时间（如通过观察账户创建时间、日志时间戳）
2. 在 ±1 秒窗口内遍历 ~10⁹ 个纳秒种子，对每个种子重跑 `generate_random_bytes(20)`
3. 用候选密钥生成 TOTP 码，与登录时观察到的 6 位码比对
4. 匹配则成功预测 MFA 密钥，绕过二因素认证

**影响**

攻击者可预测 MFA 密钥，完全绕过 TOTP 二因素认证，使 MFA 形同虚设。违反 RFC 6238 §4 要求（"The key MUST be randomly generated"）。

**修复建议**

使用 `rand::rngs::OsRng`（密码学安全 RNG）生成密钥，与 `sz-orm-crypto` 包中的 `random_bytes()` 实现保持一致：

```rust
fn generate_random_bytes(len: usize) -> Vec<u8> {
    use rand::rngs::OsRng;
    use rand::RngCore;
    let mut result = vec![0u8; len];
    OsRng.fill_bytes(&mut result);
    result
}
```

#### C-2：OAuth2 授权码使用非密码学安全随机数生成

| 属性 | 值 |
|------|-----|
| **编号** | C-2 |
| **严重级** | Critical |
| **漏洞类型** | CWE-338: Use of Cryptographically Weak PRNG；CWE-330: Insufficient Randomness |
| **OWASP** | A02:2021-Cryptographic Failures |
| **文件** | `packages/sz-orm-auth/src/oauth2.rs:264-272` |

**描述**

`generate_code()` 生成 OAuth2 授权码（authorization code），使用 `DefaultHasher` + `current_nanos()` 种子。RFC 6749 §10.10 明确要求授权码必须使用密码学安全随机数生成，以防授权码预测攻击。

**代码片段**

```rust
// packages/sz-orm-auth/src/oauth2.rs:264-272
fn generate_code() -> String {
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    let mut hasher = DefaultHasher::new();
    current_nanos().hash(&mut hasher);
    let seed = hasher.finish();
    format!("{:064x}", seed)
}
```

**PoC**

1. 攻击者发起 OAuth2 授权请求，记录请求到达服务器的精确时间
2. 在 ±1 秒窗口遍历纳秒种子，重跑 `generate_code()`
3. 获得候选授权码后，抢先于合法客户端调用 `exchange_code()` 兑换 access token
4. 成功窃取用户授权

**影响**

攻击者可预测授权码，实施授权码拦截/预测攻击，冒充用户获取 access token。违反 RFC 6749 §10.10 安全要求。

**修复建议**

使用 `OsRng` 生成 32 字节随机数后十六进制编码：

```rust
fn generate_code() -> String {
    use rand::rngs::OsRng;
    use rand::RngCore;
    let mut bytes = [0u8; 32];
    OsRng.fill_bytes(&mut bytes);
    bytes.iter().map(|b| format!("{:02x}", b)).collect()
}
```

#### C-3：令牌家族 ID 使用非密码学安全随机数生成

| 属性 | 值 |
|------|-----|
| **编号** | C-3 |
| **严重级** | Critical |
| **漏洞类型** | CWE-338: Use of Cryptographically Weak PRNG |
| **OWASP** | A02:2021-Cryptographic Failures |
| **文件** | `packages/sz-orm-auth/src/token_store.rs:466-474` |

**描述**

`generate_family_id()` 生成刷新令牌家族 ID，使用 `DefaultHasher` + `current_nanos()` 种子。家族 ID 用于令牌轮换和重放检测——若可预测，攻击者可伪造家族 ID 关联，绕过重放检测或发起令牌家族撤销攻击。

**代码片段**

```rust
// packages/sz-orm-auth/src/token_store.rs:466-474
fn generate_family_id() -> String {
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    let mut hasher = DefaultHasher::new();
    current_nanos().hash(&mut hasher);
    let seed = hasher.finish();
    format!("fam_{:016x}", seed)
}
```

**影响**

攻击者可预测家族 ID，可能绕过重放检测机制或对特定令牌家族发起定向撤销攻击（DoS）。

**修复建议**

同 C-1/C-2，使用 `OsRng` 生成 16 字节随机数。

#### H-1：JwtAuthenticator 不安全默认配置（未配置验证器时接受任意凭证）

| 属性 | 值 |
|------|-----|
| **编号** | H-1 |
| **严重级** | High |
| **漏洞类型** | CWE-1188: Insecure Default Initialization; CWE-287: Improper Authentication |
| **OWASP** | A07:2021-Identification and Authentication Failures |
| **文件** | `packages/sz-orm-auth/src/auth.rs:155-180` |

**描述**

`JwtAuthenticator` 的 `password_verifier` 字段为 `Option<Arc<dyn PasswordVerifier>>`。当未调用 `with_password_verifier()` 配置验证器时（默认状态），`authenticate()` 不验证密码，直接返回 `user_id=0` 的有效 JWT，仅通过 `eprintln!` 输出警告。

这是不安全的默认配置——开发者若忘记配置验证器，系统将默认接受任意用户名/密码组合。

**代码片段**

```rust
// packages/sz-orm-auth/src/auth.rs:165-180
let user_id: i64 = if let Some(verifier) = &self.password_verifier {
    verifier.verify_password(&credentials.username, &credentials.password)?
} else {
    eprintln!(
        "[warn] JwtAuthenticator::authenticate: password_verifier not configured; \
         accepting credentials without password verification (Critical S-1)"
    );
    0
};
```

**PoC**

```rust
let auth = JwtAuthenticator::new("secret", "issuer", 3600);
// 未调用 with_password_verifier()
let creds = Credentials::new("admin", "anything"); // 任意密码
let token = auth.authenticate(&creds).unwrap(); // 成功签发 JWT！
```

**影响**

开发者遗漏配置时，系统默认接受任意凭证，导致完全认证绕过。虽有 `eprintln!` 警告，但 stderr 警告在生产环境中常被忽略。

**修复建议**

将 `password_verifier` 改为必填参数（移除 `Option`），或在未配置时返回 `Err` 而非接受凭证：

```rust
// 方案 A：编译期保证（推荐）
pub fn new(secret: impl Into<String>, issuer: impl Into<String>, expiration: u64, 
           verifier: Arc<dyn PasswordVerifier>) -> Self { ... }

// 方案 B：运行期拒绝
let user_id = match &self.password_verifier {
    Some(v) => v.verify_password(&credentials.username, &credentials.password)?,
    None => return Err(AuthError::Config("password_verifier not configured")),
};
```

#### H-3：sz-orm-batch quote() 未转义反引号（潜在 SQL 注入）

| 属性 | 值 |
|------|-----|
| **编号** | H-3 |
| **严重级** | High |
| **漏洞类型** | CWE-89: SQL Injection |
| **OWASP** | A03:2021-Injection |
| **文件** | `packages/sz-orm-batch/src/lib.rs:170-172` |

**描述**

`BatchUpsertBuilder::quote()` 函数用反引号包裹列名，但**不转义列名中的反引号**。列名来自 `extract_columns()`，后者从 JSON 对象的 key 提取。若 JSON 数据的 key 包含反引号（如 `` `id`=?, name=`admin` -- ``），可构造 SQL 注入。

**代码片段**

```rust
// packages/sz-orm-batch/src/lib.rs:170-172
fn quote(name: &str) -> String {
    format!("`{}`", name)  // 未转义 name 中的反引号
}

// 调用处（lib.rs:388-397）
let updates: Vec<String> = non_pk.iter().map(|col| {
    let q = Self::quote(col);
    format!("{} = VALUES({})", q, q)  // 拼入 SQL
}).collect();
format!(" ON DUPLICATE KEY UPDATE {}", updates.join(", "))
```

**PoC**

```rust
// 若 rows JSON 包含恶意 key：
let row: Value = serde_json::json!({
    "id": 1,
    "`col` = (SELECT password FROM users) -- ": "x"
});
// 生成 SQL: `id`=?, `col` = (SELECT password FROM users) -- ` = VALUES(`col` = (SELECT password FROM users) -- `)
```

**影响**

当批量 upsert 的 JSON 数据来源不可信（如直接接受 API 请求体），攻击者可通过 JSON key 注入 SQL。

**修复建议**

转义列名中的反引号（MySQL 反引号转义为 `` `` `` 双反引号），或校验列名为合法标识符：

```rust
fn quote(name: &str) -> String {
    // 转义反引号
    let escaped = name.replace('`', "``");
    format!("`{}`", escaped)
}
```

#### M-5：sz-orm-graphql 生产代码 RwLock .expect() 可致 DoS

| 属性 | 值 |
|------|-----|
| **编号** | M-5 |
| **严重级** | Medium |
| **漏洞类型** | CWE-754: Improper Check for Exceptional Conditions |
| **文件** | `packages/sz-orm-graphql/src/extensions.rs:138,145,163,198,204,210,216` |

**描述**

`ResolverRegistry` 和 `RelationDataSource` 的 RwLock 操作使用 `.expect("... lock poisoned")`。若任一线程在持有锁时 panic（如解析器回调 panic），RwLock 毒化，后续所有操作均 panic，导致服务不可用。

**代码片段**

```rust
// packages/sz-orm-graphql/src/extensions.rs:138
let mut map = self.resolvers.write().expect("resolver lock poisoned");

// :145
let map = self.resolvers.read().expect("resolver lock poisoned");
```

**影响**

单一线程 panic 可级联导致整个 GraphQL 服务崩溃（DoS）。此前审计报告已修复 i18n/l2_cache/type_handler 等包的同类问题，但 graphql/extensions.rs 未修复。

**修复建议**

参照其他包的修复模式，读锁返回空/默认值，写锁跳过操作：

```rust
// 读锁降级
let map = self.resolvers.read().unwrap_or_else(|e| e.into_inner());
// 或
let map = match self.resolvers.read() {
    Ok(g) => g,
    Err(_) => return None,
};
```

#### M-6：JWT HMAC .expect() 理论 panic 风险

| 属性 | 值 |
|------|-----|
| **编号** | M-6 |
| **严重级** | Medium |
| **漏洞类型** | CWE-754: Improper Check for Exceptional Conditions |
| **文件** | `packages/sz-orm-auth/src/jwt.rs:250` |

**描述**

`hmac_sha256()` 使用 `.expect("HMAC accepts any key length")`。HMAC 规范接受任意长度密钥，RustCrypto 实现中 `new_from_slice` 对 HMAC 永远返回 `Ok`，故此分支实际不可达。但 `.expect()` 仍为潜在 panic 点，不符合防御性编程原则。

**代码片段**

```rust
// packages/sz-orm-auth/src/jwt.rs:250
let mut mac = HmacSha256::new_from_slice(key).expect("HMAC accepts any key length");
```

**修复建议**

参照 `sz-orm-crypto/src/lib.rs` 中 `hmac_sha256()` 的安全写法，用 match 处理并返回全零：

```rust
let mut mac = match <HmacSha256 as Mac>::new_from_slice(key) {
    Ok(m) => m,
    Err(_) => return [0u8; 32],
};
```

#### M-7：AI HTTP 客户端无 SSRF 防护与超时配置

| 属性 | 值 |
|------|-----|
| **编号** | M-7 |
| **严重级** | Medium |
| **漏洞类型** | CWE-918: Server-Side Request Forgery；CWE-400: Resource Consumption |
| **文件** | `packages/sz-orm-ai/src/real_embedding.rs:64`、`nl2sql.rs:840` |

**描述**

`OpenAIEmbeddingClient` 和 NL2SQL 客户端使用 `reqwest::Client::new()` 创建 HTTP 客户端，未配置：
- 请求超时（可被慢响应 DoS）
- SSRF 防护（`with_api_base()` 接受任意 URL，无私有 IP 过滤）

**代码片段**

```rust
// packages/sz-orm-ai/src/real_embedding.rs:64
http_client: reqwest::Client::new(),  // 无超时、无 SSRF 防护
```

**影响**

若 `api_base` 可被用户控制（如通过配置中心动态设置），攻击者可指向内网服务实施 SSRF。无超时配置可被慢响应 DoS。

**修复建议**

```rust
http_client: reqwest::Client::builder()
    .timeout(Duration::from_secs(30))
    .build()
    .expect("reqwest client build"),
// 并在 with_api_base 中校验 URL scheme 为 https，拒绝私有 IP
```

#### L-5：MFA TOTP 使用 HMAC-SHA1

| 属性 | 值 |
|------|-----|
| **编号** | L-5 |
| **严重级** | Low |
| **漏洞类型** | CWE-327: Use of a Broken or Risky Cryptographic Algorithm |
| **文件** | `packages/sz-orm-auth/src/mfa.rs:11` |

**描述**

TOTP 实现使用 HMAC-SHA1（RFC 6238 默认算法）。SHA1 理论上已被破解（碰撞攻击），但 TOTP 场景下 HMAC-SHA1 仍被认为安全（碰撞攻击不适用于 HMAC）。RFC 6238 同时允许 SHA256/SHA384。

**修复建议**：可选升级为 HMAC-SHA256（TOTP-SHA256），与 Google Authenticator 等保持兼容需提供配置选项。
